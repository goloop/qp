## Ментальна модель

`qp` читає параметри запиту URL у типізовані Go-значення, з опційним дефолтингом
і валідацією, і без паніки на некоректному вводі. Замість ручного танцю
`r.URL.Query().Get("age")` + `strconv.Atoi` + перевірка меж ви читаєте параметр у
потрібний тип одним викликом.

Пакет визначають три ідеї:

1. **Прочитати раз, обслужити багатьох.** Холдер `Query` декодує сирий рядок
   запиту рівно раз і відповідає на кожне читання з декодованої мапи.
2. **Композовні опції.** Дефолти й обмеження передаються як функціональні опції
   (`qp.Default`, `qp.Between`, `qp.OneOf`, …), а не позиційні аргументи, тож
   виклик читається як речення.
3. **Безпечно за замовчуванням.** `Value` завжди придатне до використання; погане
   значення відкочується до дефолту й *повідомляється* через `Error`, а не тихо
   маскується. `nil` URL ніколи не панікує. Нуль залежностей.

```go
import "github.com/goloop/qp/v2"
```

## Холдер Query

```go
func New(u *url.URL) *Query
func (q *Query) Values() url.Values
func (q *Query) Contains(key string) bool
func (q *Query) Empty(key string) bool
```

Рядок запиту рідко читають по одному параметру, тож центральний тип — це холдер,
що декодує сирий запит раз і обслуговує з нього кожне читання:

```go
q := qp.New(r.URL) // nil-safe; декодує r.URL.Query() рівно раз

page  := q.Int("page", qp.Default(1), qp.Min(1))
limit := q.Int("limit", qp.Default(20), qp.Between(1, 100))
sort  := q.String("sort", qp.Default("created_at"))
tags  := q.StringSlice("tag")
```

## Чотири родини методів

Кожен тип (`Int`, `Float`, `String`, `Bool`, `Duration`, `Time`) і його зрізова
форма пропонують чотири способи прочитати параметр, що різняться лише формою
повернення:

| Родина | Приклад | Повертає |
|--------|---------|----------|
| Bare   | `q.Int("age", qp.Default(18))` | значення (дефолт на відсутнє/невалідне) |
| Get    | `q.GetInt("age")`              | `(value, ok)` — `ok=false` на відсутнє/невалідне |
| Pull   | `q.PullInt("age")`             | `*value` — `nil`, якщо відсутнє |
| Parse  | `q.ParseInt("age")`            | повний `*Result` із прапорцями й помилкою |

Обирайте за потребою викликача: bare для «просто дай придатне значення», `Get`
коли розгалужуєтесь за валідністю, `Pull` для опційних полів (`nil` вказівник
означає «не надано»), і `Parse` коли потрібна повна картина.

`Result[T]` несе все, що дізнався парсинг:

```go
type Result[T any] struct {
    Key      string // ім'я параметра
    Value    T      // розпарсене значення або дефолт, якщо відсутнє/порожнє/невалідне
    Default  T      // дефолт, застосований коли значення непридатне
    Contains bool   // параметр присутній у запиті
    Empty    bool   // відсутній або присутній без значення
    Error    error  // не-nil, якщо присутнє непорожнє значення відхилено
}
```

## Опції

Скалярні опції обмежують одне значення:

```go
qp.Default(v)        // значення, коли відсутнє, порожнє чи невалідне
qp.Min(v)            // відкрита нижня межа
qp.Max(v)            // відкрита верхня межа
qp.Between(lo, hi)   // включний діапазон, межі авто-міняються місцями
qp.OneOf(a, b, c)    // дозволений набір (спосіб валідувати рядки)
```

Зрізові опції формують читання зрізу:

```go
qp.Each(opts...)     // застосувати скалярну валідацію до кожного елемента
qp.Sep(";")          // власний роздільник (дефолт ",")
qp.Fallback(v)       // дефолтний зріз, коли відсутнє, порожнє чи невалідне
qp.KeepEmpty()       // лишати порожні елементи замість викидання
qp.ErrorOnEmpty()    // відхилити весь зріз на будь-якому порожньому елементі
```

`Min`/`Max`/`Between` вимагають упорядкованого типу; `OneOf` вимагає порівнюваного
типу й є ідіоматичним способом валідувати рядки проти дозволеного набору.

## Контракт валідації

`Value` завжди безпечне у використанні. Коли **присутній, непорожній** параметр
не парситься чи порушує обмеження, `Value` відкочується до дефолту, а `Error`
пояснює чому — відмова повідомляється, а не тихо маскується:

```go
r := qp.ParseInt(u, "age", qp.Default(18), qp.Between(18, 65))
// "?age=99": r.Value == 18, r.Error != nil
// GetInt повернув би (18, false); PullInt — вказівник на 18.
```

**Відсутній** чи **присутній-але-порожній** параметр — не помилка: він просто дає
дефолт, а `Error` лишається `nil`. Використовуйте помічники наявності, щоб їх
розрізнити.

## Наявність: Contains і Empty

```go
if q.Contains("id") {
    // "id" було надано (можливо, як "?id=")
}
if q.Empty("id") {
    // "id" відсутнє або надано з порожнім значенням
}
```

`Contains` повідомляє, чи ключ узагалі з'являється; `Empty` — чи він відсутній
або присутній без значення. Разом вони розрізняють «не надіслано», «надіслано
порожнім» і «надіслано зі значенням».

## Кастомні типи

Для типів поза `int`/`float64`/`string`/`bool` родина `As` бере функцію парсингу;
`Duration` і `Time` — готові:

```go
import "net/netip"

addr, ok := qp.GetAs(q, "ip", netip.ParseAddr)

ttl  := q.Duration("ttl", qp.Default(30*time.Second), qp.Max(time.Hour))
from := q.Time("from", time.RFC3339)
```

`GetAs`/`PullAs` (і `GetSliceAs`/`PullSliceAs`) приймають будь-яку
`func(string) (T, error)`, тож будь-який тип із парсером під'єднується до тих
самих опцій, дефолтингу й валідації.

## Зрізи

Зрізові параметри приймають кому-форму, повторювану форму й їхні суміші, усі
нормалізовані однаково: кожне значення ділиться роздільником, кожен елемент
обрізається, а порожні елементи за замовчуванням викидаються. Один невалідний
елемент відхиляє весь зріз.

```go
u, _ := url.Parse("http://example.com?ids=1,2&ids=3")
ids := qp.IntSlice(u, "ids", qp.Each(qp.Between(1, 100))) // [1 2 3]
```

`KeepEmpty` зберігає порожні елементи; `ErrorOnEmpty` перетворює будь-який
порожній елемент на відхилення; `Sep` змінює роздільник; `Each` застосовує
скалярні опції до кожного елемента; `Fallback` дає зріз, що використовується,
коли параметр непридатний.

## Помилки

Помилки обгортають типізовані сентинели плюс `*ParseError` із ключем і хибним
значенням:

```go
var (
    ErrInvalid      // значення не вдалося розпарсити як цільовий тип
    ErrNotAllowed   // значення порушило обмеження (діапазон / OneOf)
    ErrEmptyElement // елемент зрізу порожній під ErrorOnEmpty
)

type ParseError struct {
    Key   string // ім'я параметра
    Value string // хибне сире значення (порожнє для ErrEmptyElement)
    Err   error  // обгорнутий сентинел
}
```

Звіряйте через `errors.Is`, а деталь витягайте через `errors.As`:

```go
if errors.Is(r.Error, qp.ErrNotAllowed) {
    var pe *qp.ParseError
    errors.As(r.Error, &pe) // pe.Key, pe.Value
}
```

## Пакетні шорткати

Для одного читання є пакетні функції, що будують одноразовий холдер із
`*url.URL`, дзеркалячи методи холдера:

```go
age, ok := qp.GetInt(r.URL, "age", qp.Between(18, 65))
role    := qp.String(r.URL, "role", qp.Default("guest"), qp.OneOf("admin", "user"))
ids     := qp.IntSlice(r.URL, "ids", qp.Each(qp.Between(1, 100)))
```

Надавайте перевагу `qp.New(u)`, коли читаєте кілька параметрів з того самого URL,
щоб запит декодувався раз.

## Рецепти й поради

**Декодуйте раз на запит.** Збудуйте один `qp.New(r.URL)` на початку хендлера й
читайте з нього кожен параметр, замість повторних викликів пакетних функцій.

**Опційні SQL-фільтри.** Методи `Pull` роблять опційні фільтри лаконічними —
`nil` вказівник означає «не надано», тож у `WHERE` потрапляють лише присутні
параметри:

```go
q := qp.New(r.URL)
active := q.PullBool("is_active")   // *bool або nil
if active != nil { /* додати "is_active = ?" */ }
```

**Валідуйте рядки через `OneOf`.** Для рядків немає діапазону; обмежте їх
дозволеним набором і поєднайте з `Default` для запасного варіанта.

**Повідомляйте, не ховайте.** Коли вам важливо *чому* значення відхилено,
використовуйте родину `Parse` й дивіться `Result.Error`; форми bare/`Get`/`Pull`
вже безпечно застосовують дефолт.

**Власні роздільники й типи.** Беріть `Sep`, коли клієнти шлють `a;b;c`, і
`GetAs`, коли значення — це `netip.Addr`, токен на кшталт UUID чи будь-який тип
із парсером `func(string) (T, error)`.
